Takeaways of the week

  • Start proactive agents with read-only access. Grant an agent inbox and calendar viewing first and widen permissions only after you trust its judgment. Day 229
  • Demand consent gates on irreversible actions. Pick agents that stop for approval before payments, signatures, sending and deletion, and read each request instead of auto-approving. Day 229
  • Route by difficulty. Send routine agent steps to a cheap fast tier and escalate only hard tasks to the flagship, then measure cost per completed task. Day 228
  • Test destructive actions separately. A model that is safer on average can still delete or overwrite more, so run your own dry-run tests on file and database operations. Day 228
  • Give background agents the smallest permissions that work. Start read-only, then add write access one action at a time, because an always-on agent will use every permission you grant. Day 227
  • Log every agent action. Keep a reviewable trail of what the agent did and why, so you can catch mistakes that happen while nobody is watching. Day 227
  • Treat voluntary commitments as signals, not guarantees. Check whether a pledge includes disclosure or audit rights before relying on it in vendor reviews. Day 226
  • Read the S-1 when it lands. It will be the best public source on frontier-lab costs, risks and governance. Day 226
  • Add the AI training opt-out to your site. If you publish content, watch for the final robots.txt syntax and add it once the draft stabilises, while keeping existing per-crawler rules. Day 225
  • Treat the signal as a request, not a lock. It only binds compliant crawlers, so sensitive material still needs authentication or paywalls. Day 225
