Takeaways of the week

  • Give each agent its own identity. Use a dedicated account or service identity with narrow rights, never a person's login. Day 196
  • Log every agent action. If regulators or auditors ask what an agent did, you need a record with who approved it. Day 196
  • Route by step difficulty. Use the cheapest tier for simple steps and reserve top tier and high effort for the hard ones. Day 195
  • Measure cost per finished task. Include latency, retries and cached input, not only the per-token price. Day 195
  • Wait for independent numbers. Give a new model a few days and check third-party indexes before changing a production default. Day 194
  • Track cost per token, not just price per token. Ask about cached input, latency and throughput, since hardware gains show up there. Day 194
  • Test agents for honesty, not only accuracy. Compare what the agent says it did with its action log on a sample of runs. Day 193
  • Do not rely on a model you cannot access yet. Plan around what is generally available (Sol, Sonnet 5.5, Opus 5.5) and treat Argon as a watch item. Day 193
  • Route by task, not by brand. Send routine agent steps to a near-flagship cheaper model like GPT-6.1 Sol and keep the top model for hard steps; measure quality before switching. Day 192
  • Design prompts for caching. Put stable instructions and reference files first and keep them identical across calls, so cached-input pricing applies. Day 192
  • Treat an access-denied response as a hard stop for agents. If you run agents against systems you do not own, put that in the agent's instructions and code (no retries via alternate routes) and log every refusal so a human can review it. Day 191
  • Decide now how fast you would disclose an AI incident, and to whom. The Medicare case shows a roughly three-month gap and a message to a generic mailbox; the delay became the story itself. Day 191
  • If you build or deploy agents that run in a "sandbox," audit which outbound services are allow-listed -- link shorteners, pastebins, and other generic redirectors can become a covert channel exactly the way they did at Hugging Face. Restrict to a specific, reviewed destination list, not a category of "safe-looking" services. Day 190
  • If you're evaluating multi-agent tools, look at how they represent an agent's identity and permissions (as Ando does) rather than treating it as an API key sitting behind a bot account -- clearer agent identity now is what will make audit and access control possible later. Day 190
