Anthropic Lets Agents Approve Code, Z.ai Runs a Model's Layers Twice, and OpenAI and Cisco Shield Unpatched Servers

Claude Ship puts AI agents on both sides of a code review, GLM-5.4 reuses 28 layers instead of adding new ones, Shirudo lets agents write temporary shields for running Linux servers, Amazon pays a reported $7.5 billion for Decart's chip software, two states sue SpaceX over Grok's deepfakes, and fast-anything ports only the slow 5% of an app to Rust.

Infrastructure & Economics Models & Frontier
Viral / open-source spotlight

Fast-anything: have a coding agent port only the slow 5% of an app to Rust, and prove it

fast-anything (github.com/EL4CTEO/fast-anything) is an open-source command-line tool with a blunt motto: do not rewrite your program in Rust, rewrite the 5% that is slow. Rust is a programming language known for speed, and rewriting a whole application in it is a famously long project. This tool does the small version. It first profiles the running app, written in Python, JavaScript, Ruby, Go, Java, PHP or several other languages, and ranks its functions by how much time they take and how easy they are to move. For a chosen function it records up to 500 real calls, the inputs that arrived and the answers that came back, then writes a brief for a coding agent such as Claude Code or Codex to produce a Rust version. Then comes the part that matters: it replays every recorded call through the new code, adds awkward cases of its own such as empty and very large inputs, and compares the results with the original. The Rust version is switched on only if every case matches and it is in fact faster; one setting switches it off again. The repository page showed about 3,600 stars and 257 forks when we read it, under the MIT licence. The author's own examples report speed-ups from 2.7 times to 116 times. Why it is taking off: Coding agents made writing a Rust port cheap; what was missing was a reason to trust it. Recording real behaviour and replaying it is that reason, and it is the same idea as the Lean checker on Day 241 at everyday scale: the agent's work is accepted because an independent test says it behaves the same, not because the agent says so. It also fits a wider turn among developers from generating more code to making existing code cheaper to run. The caveats: only simple, deterministic functions that take plain data qualify, the speed figures are the author's own on small demo programs, 500 recorded calls cannot cover every input a function will ever see, and we found no independent review or security audit. Also trending: mobile-agent-testers, which runs Claude Code agents as test users on emulated phones, and agentes-chat, a self-hosted team chat where agents are channel members with budgets.

Part 1Claude Ship Puts Agents on Both Sides of Code Review

On November 23 Anthropic released Claude Ship in beta, according to press reports. It is a bundle of agents for what happens after code is written, the stage where a proposed change, called a pull request, waits to be checked and merged. It combines three parts. Code Review, already generally available, reads a pull request and posts findings. PR Steward, new and in beta, looks after the pull request and makes the fixes; we could not open Anthropic's page to confirm exactly which chores it handles. Claude Approvals, also in beta, can approve a change on the team's behalf. It is offered to Team and Enterprise customers whose code is on GitHub. A developer starts it with a /ship command in Claude Code, and administrators can switch Code Review and PR Steward on for a whole repository so they run without the command. Approvals follow a policy the team writes: it can let Claude approve routine changes while requiring named people for sensitive ones. Anthropic recommends running approvals in an observation-only mode first, where the agent records what it would have decided without deciding anything. Usage is billed by tokens with monthly spending caps, and Anthropic warns that the agents can miss bugs and security flaws and should be one layer of a wider process. The concept, explained simply: Separation of duties is the old rule that the person who does a job should not be the one who signs it off. A cashier does not audit their own till. Code review exists for the same reason: a second pair of eyes catches what the author cannot see. When an AI writes the change, another AI fixes it and a third approves it, the second pair of eyes may share the first pair's blind spots. The safeguard on offer is policy-based approval: the team decides in advance which kinds of change are routine enough for the agent and which must go to a named human. Observation-only mode, often called shadow mode, is how you test such a policy, like a trainee pilot flying the simulator before the aircraft. Why it matters: Coding agents have made writing code fast, and review has become the queue where work waits. Claude Ship is aimed at that queue, and LoopForge (Day 240) and Plannotator (Day 235) attacked the same problem from the other side by adding human gates. The risk is plain: an approval is a control that auditors and security teams rely on, and handing it to the same vendor's model that wrote the code weakens it unless the policy is narrow. Expect the question in audits to shift from who approved this to which policy allowed an agent to.

Part 2Z.ai's GLM-5.4 Runs 28 of Its Layers Twice

Z.ai, the Chinese lab behind the GLM models, announced GLM-5.4 on November 23 and calls it the first flagship model built as a Loop Transformer. A language model is a tall stack of layers, and text normally passes through each layer once. By press accounts of Z.ai's diagram, GLM-5.4 has 78 distinct layers: the input passes through layers 1 to 26 once, through layers 27 to 54 twice, then through layers 55 to 78 once. That makes 106 layer passes from 78 layers' worth of stored weights. The model has about 750 billion parameters, and Z.ai claims it performs like models of two to three trillion. The evidence is thin so far. Z.ai published no benchmark scores for the full model; the gains it reports in mathematics, scientific reasoning and long-context work come from a small 30-billion-parameter test version that used the same parameter count and about 10% more training compute. There is no API and no download: the model is available only inside Z.ai's own products, including its GLM Coding Plan. The concept, explained simply: A model's parameters are its stored knowledge, and its layers are the steps of thinking it applies to each word. The usual way to get a smarter model is to add more layers, which means more parameters to store and train. A looped design reuses layers instead. Think of proofreading an essay: you can hire a second editor, or you can ask the same editor to read it twice. The second reading costs time but no extra salary, and it often catches things the first missed. The cost is real, though: every word now takes more computing to produce, so answers are slower or dearer to serve. Z.ai says a caching trick limits that extra cost, a claim nobody outside the company has measured. Why it matters: Under export controls (Day 239), Chinese labs are short of the best chips, so ideas that buy capability with cleverness rather than size matter most to them. If looping holds up, parameter count becomes a worse guide to how capable a model is, which complicates any rule or comparison built on size. For buyers the lesson is older: a claim of trillion-class ability with no published scores and no outside access is a hypothesis. Wait for independent tests, and ask about speed and price per answer as well as quality.

Part 3OpenAI and Cisco's Shirudo Shields Unpatched Servers

On November 23 OpenAI and Cisco released Shirudo, an open-source tool that lets AI agents write temporary protections, called shields, for running Linux servers. When a new vulnerability is disclosed, attackers can have a working exploit in hours, while testing and installing the proper fix often takes a company days or weeks. A shield is a small program that blocks the specific attack during that gap without stopping the service. Shirudo is built on Tetragon, the security project from Isovalent, now part of Cisco, and is reported to carry a BSD two-clause licence. In the demonstration, OpenAI's Codex wrote a shield for Java4Shell, a recently disclosed flaw in OpenJDK, that changed how Java's Base64 decoder behaved inside a running Elasticsearch 9.5.5 server and blocked the exploit in a controlled test with no restart. Each shield is cryptographically signed and checked before it loads, and operators can watch what a shield would do before letting it enforce. It is not ready for production: reports describe a pre-release that needs a specially patched kernel and a TPM 2.0 security chip. Security researcher Marcus Hutchins questioned whether AI agents should be writing rules that reach into the kernel at all. The concept, explained simply: eBPF is a way to load small, checked programs into the core of a running Linux system, the kernel, without rebuilding or restarting it. Think of the kernel as a building's reception desk that every visitor must pass. eBPF lets you hand the receptionist a new instruction card while the building stays open. Virtual patching uses that to block an attack from outside the faulty software: instead of repairing the broken lock on one office door, which means closing the office, you tell reception to turn away anyone carrying that particular crowbar. The broken lock is still there, so the real fix is still needed. The shield only buys time. Why it matters: AI has sped up attackers: OpenAI's first model rated critical for cyber (Day 236) and the open-source hacking kit that hit EU payroll (Day 238) both shortened the time from disclosure to exploit. Shirudo is an attempt to shorten the defender's side to match. The trade is trust: a wrong shield in the kernel can break the very service it protects, which is why signing and the watch-first mode matter more than the agent's cleverness. The pattern is the one from Day 241: accept AI-written work when a small, independent check stands between it and production.

Part 4Amazon Pays a Reported $7.5 Billion for Chip Software

Amazon said it has agreed to buy the technology behind the Decart Optimization Stack, software from the Israeli startup Decart that makes AI models run faster on a given chip, and to hire Decart's founders and its research and engineering team. Amazon gave no price; Bloomberg, citing a person familiar with the deal, put it at about $7.5 billion including later payments tied to conditions. Decart was valued at roughly $4 billion when it raised $300 million in May. Its own AI models, the Lucy and Oasis video models, are reported to be outside the deal. One Israeli report says the three founders have committed to five years at Amazon. Decart says its stack runs on Nvidia graphics chips, Amazon's Trainium and Google's TPUs; Amazon's aim, by press accounts, is to get more out of Trainium, the in-house chip it uses to compete with Nvidia. The deal still needs regulatory clearance. Separately, Nvidia shares fell about 5.9% on Tuesday to $155.38, returning part of Monday's 31% jump after Jensen Huang's reinstatement (Day 241); the Nasdaq lost about 1.5%.

The concept, explained simply: A chip's speed on paper is not the speed you get. Between an AI model and the silicon sits a pile of software that decides how the model's arithmetic is split up, ordered and packed into the chip's memory. Nvidia's lead rests heavily on this layer, built up over nearly twenty years, as well as on its hardware. An optimisation stack is that layer done well: like a removal crew that fits the same furniture into one lorry instead of two, it gets more work out of the same machine. A deal for technology and people, leaving the company and its products behind, is the structure big technology firms now favour because it is quicker than a full takeover, though regulators have started to look at such deals as acquisitions in all but name. Why it matters: Every large cloud company now designs its own AI chips, such as Google's TPU 8 line (Day 229), and the weak point is usually software, not silicon. Paying nearly twice a startup's last valuation for a tuning layer shows where the value sits. For customers it means the cheapest place to run a model will depend more and more on which software stack it was tuned for, so price comparisons need to be run on your own workload, and moving a tuned model between clouds may cost more than expected.

Part 5Virginia and Oregon Sue SpaceX Over Grok's Deepfakes

On November 23 the attorneys general of Oregon and Virginia, Dan Rayfield and Jay Jones, filed separate lawsuits in their state courts against SpaceX, which acquired xAI, the maker of the Grok chatbot, in February. They allege the company failed to put safeguards in place to stop Grok and users of X from making and sharing sexualised deepfake images, including alleged AI-generated child sexual abuse material. Several states had opened investigations; these are the first to sue. The legal route is the notable part. The complaints say the company presented its AI apps and social network as generally safe when they were not, which the states argue breaks Virginia's Consumer Protection Act and Oregon's Unlawful Trade Practices Act. They cite marketing of Grok as a companion with a rebellious streak and a study estimating that Grok produced about three million sexualised images on X between December 29, 2025 and January 8, 2026. They seek civil penalties and court orders requiring guardrails. The company said such material has no place on X or in Grok and that it keeps updating its safeguards. Outlets differ on exactly which corporate entities are named, and nothing has been tested in court. The concept, explained simply: There are two ways to hold a company to account for what its product puts out. One is to argue the output itself is unlawful and the company is responsible for it, a route that for online platforms runs into long-standing legal protections for content posted by users. The other is to argue the company misdescribed its product: it said the thing was safe, and it was not. That is a deceptive-practices claim, the same law used against a car maker that advertises brakes it knows are faulty. It does not ask the court to judge each image, only whether the safety promises matched the reality.

Why it matters: State attorneys general are becoming the front-line AI regulators in the United States while federal rules stall, as with California's case against OpenAI over agents (Day 235) and the governors' plan (Day 240). The deceptive-practices route is one any state can copy, and it applies to every AI vendor: marketing claims about safety are now a legal exposure. If you buy or build AI products, treat the safety page as a contract. Say only what you can show with test results, and keep the evidence.

Market signal

The signal is that the money and the engineering are moving from producing AI output to the steps around it. Anthropic is selling review and approval, the stage after the code exists. Amazon is paying billions for software that makes chips it already owns run faster. Z.ai is chasing capability by reusing layers it already has. And the market itself paused: Nvidia handed back roughly a fifth of Monday's gain on Tuesday, a reminder that one boardroom decision did not settle the questions about governance and financing. Expect more purchases of optimisation software and teams by chip owners, pricing that charges for checked and merged work as well as generated tokens, and vendors' safety claims to be read by state lawyers as promises.

Practical takeaways
Write the approval policy before you switch on an approving agent.

List which kinds of change an AI may approve and which need a named person, and keep security, payments and access-control code on the human list.

Run new automation in shadow mode first.

Let the agent record what it would have decided for a few weeks, compare that with what people decided, and only then give it authority.

Do not let one model family write, fix and approve the same change.

Keep at least one check, a person, a test suite or a different tool, that does not share the author's blind spots.

Treat a model claim without scores as a hypothesis.

For any new architecture, wait for independent benchmarks and ask about speed and cost per answer, not only quality.

Plan for the gap between disclosure and patch.

Know which of your systems can be shielded or isolated within hours, and treat any temporary block as a stopgap with a date for the real fix.

Benchmark on your own workload before choosing a cloud chip.

Performance depends on the software stack as much as the silicon, so test your model on each option and note what moving later would cost.

Make safety claims only where you hold the evidence.

Review marketing and product pages for statements about safety and keep the test results that support each one.

Record real behaviour before you let an agent rewrite code.

Capture actual inputs and outputs of the old code and accept the new version only when it reproduces them.

Self-test
What three parts make up Claude Ship, and which of them were new in beta?

Code Review, PR Steward and Claude Approvals; Code Review was already generally available, and the other two were new in beta.

What is shadow or observation-only mode, and why use it before letting an agent approve changes?

The agent records what it would have decided without acting, so a team can compare its judgement with human decisions before giving it authority.

GLM-5.4 has 78 layers but makes 106 layer passes. How?

Layers 27 to 54, 28 in all, are run twice with the same weights, so the model gets more steps of processing without storing more parameters.

What does a Shirudo shield do, and what does it not do?

It blocks a specific exploit on a running Linux server while the real patch is prepared; it does not repair the flaw, which still needs fixing.

Why would Amazon pay billions for software when it already designs its own AI chips?

Because how fast a model runs depends heavily on the software between model and chip, the layer where Nvidia's lead is strongest.

What legal theory do Virginia and Oregon use against SpaceX over Grok?

Deceptive practices under state consumer-protection law: they say the products were presented as safe when they were not.

How does fast-anything decide whether to switch on a Rust port written by an agent?

It replays up to 500 recorded real calls plus edge cases through the port and enables it only if every result matches the original and it runs faster.
