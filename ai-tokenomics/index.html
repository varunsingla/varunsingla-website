01 — Fundamentals

What is a Token?

Tokens are the atomic unit of AI computation — not characters, not words, but sub-word fragments that every LLM uses to read input and write output. Understanding them is understanding the bill.

≈ 0 tokens  ·  0 chars  ·  ratio: 0 chars/token
1 token ≈ ¾ of an English word — but tokenisers now diverge

Common words are 1 token; rare words split into multiple. Code is densest. And as of 2026, tokenisers differ materially by model: Claude Opus 4.7+, Opus 5/5.5, Fable 5/5.1 and Sonnet 5/5.5 produce ~1.0–1.35× (typically ~30%) more tokens for the same text than Opus 4.6 / Sonnet 4.6 / Haiku 4.5 — so $/MTok is not comparable across tokeniser generations.

Output tokens cost 3–5× more

GPT-6 Astra: $10 input vs $50 output per MTok. Claude Opus 5.5: $4 vs $20. GPT-6.1 Sol and Claude Sonnet 5.5: $2 vs $10. Output is 5× input on most current flagships (Grok 4.7 and Qwen3.8-Max: 3×) — a model that writes a lot costs far more than one that reads a lot, though the 2026 price war has compressed the ratio from the old 4–10×.

Reasoning models have hidden token cost

GPT-6 Astra / 6.1 Sol (reasoning effort), Claude Opus 5.5 (thinking always on, effort default medium) and Claude Fable 5.1 (always on) generate internal chain-of-thought tokens that are billed as output but never shown to you — often 3–10× the visible output.

Agentic loops fan-out 5–50×

One user request can trigger 5–50 LLM + MCP tool calls. Simple agents use 5K–15K tokens per task; complex multi-agent systems consume 200K–1M+ tokens per task. This is the dominant cost story of 2026.

03 — Core Optimisation

10 Levers to Cut Token Spend

These are proven, production-tested techniques. Combined, organisations routinely achieve 40–80% cost reduction. Start with the high-impact ones — they require minimal engineering effort.

01
Biggest Lever

Prompt Caching (KV Cache)

Providers cache the key-value matrices of repeated prompt prefixes. This is the single highest-impact optimisation — up to 90–97.5% cheaper on cached input tokens with minimal code changes.

October 2026 Provider Cache Pricing
  • Anthropic cache reads: 0.1× base input on most models — 0.05× on Opus 5.5 ($4 → $0.20) and 0.025× on Fable 5.1 ($10 → $0.25). Writes 1.25× (5-min) / 2× (1-hour). Batch 50% stacks with caching
  • OpenAI GPT-6 family: reads 90% off (Astra $1.00, Luna $0.01) and 95% off on GPT-6.1 Sol ($0.10); writes 1.25× from GPT-5.6 on; changing effort or tools mid-conversation no longer breaks the cache
  • Google Gemini: reads ~10% of input on Flash (95% off on Argon), plus hourly cache storage ($0.50–$1.00 per M tokens/hr on Flash, $4.50 on 3.1 Pro)
  • DeepSeek V4.1 Flash: $0.006 cache hit at peak, $0.003 off-peak (98% off)
  • Min cacheable prefix: 512 tokens on Opus 5/5.5, Fable 5/5.1, Sonnet 5.5; 1,024 on Sonnet 5 / Sonnet 4.6 / Opus 4.8; 4,096 on Haiku 4.5
  • TTL: 5 min standard; Anthropic 1-hour option (2× write) — on Fable 5.1 a keep-alive request is usually cheaper than the 1-hour TTL
Implementation: Place stable content first — system prompt, docs, tool definitions, MCP tool schemas. Place dynamic content last — user queries, session data. Anthropic: use cache_control parameter for explicit breakpoints. Target 80–95% hit rate. October 2026 note: cache reads now cost anywhere from 1/40 of list input (Claude Fable 5.1, $10 → $0.25) to 1/10 (GPT-6 Astra, $10 → $1.00) — a 4× spread at the same $10 sticker, and 10× in absolute terms from GPT-6.1 Sol's $0.10 to Astra's $1.00. On long agent loops the cache rate, not the list price, sets the bill — OpenAI says its GPT-6 caching upgrade more than halved freshly processed tokens across GitHub Copilot.
Up to 90–97.5% off input tokens
02
High Impact

Multi-Model Routing — The 70/25/5 Rule

The 2026 default architecture. Send 70% of traffic to nano-tier (GPT-6 Luna / DeepSeek V4.1 Flash / Qwen3.8-Flash / Gemini 3.5 Flash-Lite) for classification + simple tool calls, 25% to mid-tier (Claude Sonnet 5.5 / GPT-6.1 Sol / Gemini 3.8 Flash / GLM-5.3) for structured reasoning, and only 5% to frontier (Claude Opus 5.5 / Fable 5.1 / GPT-6 Astra) for ambiguous planning. Cost runs at ~23% of sending everything to Claude Opus 5.5 ($5,439 vs $23,550/mo in the agentic scenario above), with statistically indistinguishable quality on 200-pair golden sets. The October twist: route on two axes — tier AND effort. One independent test found GPT-6 Sol at maximum effort only narrowly beats GPT-6 Astra at minimum effort while costing more per task, and Claude Sonnet 5.5 at medium costs ~1/13 of its max-effort run. Sakana's Fugu Ultra v2.0 ($5/$30) even sells routing as a model.

2026 routing strategies (production-validated)
  • Static rules (intent → model map): 30–40% cost reduction, <5 min to ship
  • Embedding-based (k-means buckets): 50–70% reduction
  • Trained classifier (RouteLLM-style): 65–85% reduction
  • Cascade with confidence threshold: 70–85% reduction — 2026 default
  • Architecture lifts (42%→78%) outperform model upgrades alone
Implementation: LiteLLM (33K+ stars, OpenAI-compatible proxy, 100+ providers) is the safest first move. Portkey for enterprise gateway features. Bifrost (Rust) for sub-ms latency. Watch for: cascade thrash (threshold too high → escalates everything), tool-schema mismatch across providers, context-window asymmetry. Wire OTEL gen_ai spans BEFORE turning on routing. Pin exact gateway versions and hashes — poisoned LiteLLM 1.82.7/1.82.8 were live on PyPI for ~40 minutes on Aug 13 and stole cloud, SSH and Kubernetes credentials.
70–85% reduction at frontier-equivalent quality
03
High Impact

Truncate & Summarise Conversation History

Every message in a multi-turn chat is resent on every call. A 40-turn conversation carries 25,000+ input tokens — the largest invisible cost driver. Sliding window truncation + summarisation eliminates this.

Implementation patterns
  • Sliding window: Keep only last N turns
  • Summarisation: After 10 turns, compress older history to 1 paragraph
  • Structured state: Extract facts into a key-value store, not raw chat
  • Topic clear: Reset context on new user intent/topic
  • Max messages limit: Hard-cap turns per session in agent platforms
Implementation: Use a cheap model (GPT-6 Luna, Haiku 4.5, Gemini 3.5 Flash-Lite) to summarise older context before the main call. The summarisation cost is negligible vs the savings. Context engines with this pattern achieve 40–60% input reduction. Anthropic and OpenAI now ship server-side compaction for long agent sessions.
40–70% context token reduction
04
High Impact

Semantic Caching

Instead of caching exact strings, semantic caching uses vector embeddings to serve cached responses when queries are semantically similar (≥0.85–0.95 cosine similarity). Avoids the API call entirely for repetitive queries.

2026 production benchmarks
  • Cache hit rates: 60–85% in support/FAQ workloads
  • API call reduction: up to 68.8% fewer calls
  • Latency: 1.67s → 0.052s per cache hit (96.9% faster)
  • Cost reduction: up to 73% on conversational workloads
  • 31% of LLM queries show semantic similarity — often untapped
Implementation: Redis with LangCache, Portkey, Helicone, or Bifrost all support semantic caching in 2026 via one-line gateway integration. Namespace by model + provider to avoid cross-contamination. Skip caching for conversations exceeding ~10 turns to reduce false positives.
50–73% on semantically repetitive workloads
05
Medium Impact

Concise Prompt Engineering

Verbose prompts don't produce better outputs — they just cost more. Filler phrases like "You are a helpful, professional, knowledgeable assistant" add tokens with zero information gain. Telling a model to "be concise" reduces output tokens by 57–59%.

Before → After
You are a helpful, knowledgeable, friendly, professional customer support agent who always responds in a polite and courteous manner and ensures customer satisfaction...
↓ 55% fewer tokens, same output quality
You are a customer support agent. Be concise and accurate.
Implementation: Audit every system prompt. Remove filler, pleasantries, and redundant instructions. LLMLingua prompt compression achieves 20× token reduction with only 1.5% quality loss — available as a plug-and-play LangChain/LlamaIndex integration.
30–55% prompt size reduction
06
Medium Impact

Constrain Output Length & Format

Output tokens typically cost 3–5× more than input. Setting max_tokens limits and requesting structured JSON instead of prose cuts the most expensive part of every call.

Control techniques
  • Set explicit max_tokens parameter per call type
  • Request JSON/structured output schemas: ~15% token reduction vs prose
  • Use stop sequences to prevent unnecessary continuation
  • Request bullet responses: "Answer in 3 bullet points"
  • Use "be concise" instruction: 57–59% output reduction (OPSDC research)
Implementation: Map output length requirements to use-case type. FAQ = 1–2 sentences. Summary = 3–5 bullets. Analysis = structured JSON. Set max_tokens as a hard upper bound for each use-case tier.
15–60% output token reduction
07
Medium Impact

RAG Context Compression

RAG pipelines often dump entire document chunks into context — including sentences irrelevant to the query. Pre-filtering retrieved chunks to only query-relevant sentences cuts RAG input tokens by 50–80% with maintained accuracy.

Optimised RAG pipeline
  • Retrieve top-K chunks (e.g. 10 chunks)
  • Score each sentence for query relevance (cheap model)
  • Pass only high-relevance sentences (~20% of retrieved text)
  • Reduce Top-K from 10 to 3–5 via hybrid search
  • Result: same answer quality, 50–80% fewer tokens
Implementation: Use a small model (Gemini 3.5 Flash-Lite, GPT-6 Luna, Haiku) or a BM25/reranker to score and filter context before passing to the main LLM. One production case study: cost per contract dropped from expensive to $0.91, with 40% latency reduction.
25–80% RAG context reduction
08
Medium Impact

Batch Processing

Most providers offer 50% discounts for asynchronous batch API calls. Non-real-time workloads — nightly reports, document analysis, bulk classification — are ideal candidates with zero quality trade-off.

Batch API discount (2026)
  • OpenAI Batch / Flex: 50% off (GPT-6.1 Sol $1/$5)
  • Anthropic Message Batches: 50% off every token, including cache reads/writes (Fable 5.1 $5/$25)
  • Google Gemini Batch / Flex: 50% off
  • SpaceXAI: 20% batch discount only on Grok 4.3 / 4.20 — none on Grok 4.5–4.7
  • DeepSeek peak/off-peak (Aug 16): peak = 2× off-peak, Mon–Fri 09–12 & 14–18 Beijing; weekends off-peak — off-peak scheduling is a batch-style lever in its own right
  • Inverse lever: paid speed tiers (Claude Opus 5.5 fast mode 2×; OpenAI Fast 2× / Ultrafast 6×) — only for interactive loops, never overnight jobs
  • Use cases: doc processing, bulk tagging, analytics, embeddings — minutes to 24 hours turnaround (vs milliseconds sync)
Implementation: Audit all AI calls for real-time necessity. Most analytics, classification, and reporting workflows can be shifted to batch. No engineering complexity — just use the batch endpoint.
50% off all eligible non-real-time workloads
09
Targeted Impact

Avoid Reasoning Models for Simple Tasks

Reasoning models — Claude Opus 5.5 (thinking can't be disabled; effort default medium), Claude Fable 5.1 (always on), Claude Sonnet 5.5 (defaults to high; thinking off only via between_tools), GPT-6.x (reasoning effort) — generate internal chain-of-thought tokens before responding: billed but invisible. CoT can be 3–10× the visible output. For a FAQ bot or classifier, you may be paying 5–20× more than necessary.

When to use reasoning models
  • ✓ Multi-step mathematical/logical deduction
  • ✓ Code debugging with complex dependency chains
  • ✓ Long-horizon agentic planning (orchestrator role only)
  • ✓ Legal/financial analysis requiring step-by-step reasoning
  • ✗ Summarisation, classification, translation, FAQ
  • ✗ Sub-agent tool calls — use GPT-6 Luna / Haiku 4.5 / Qwen3.8-Flash instead
Implementation: Set the effort parameter explicitly per call type — never inherit the default. Reserve high/xhigh/max for tasks a classifier scores as multi-step.
5–20× cost reduction vs always-on reasoning
10
Enabler

Fine-Tuning for Repetitive High-Volume Tasks

Fine-tuning embeds task knowledge directly into the model, eliminating the need for lengthy few-shot examples in every prompt. For stable, high-volume tasks, fine-tuned smaller models can outperform generic larger ones at a fraction of the cost.

Economics (2026)
  • Open-weight fine-tuning: GLM-5.3-Flash, Qwen3.8-27B and Gemma 4 are permissively licensed bases
  • Inference savings: 40–60% fewer tokens per call
  • Self-hosted open-weight fine-tunes: savings reach 20–25× vs proprietary API
  • Break-even: typically ~1M calls on the specific task
  • Only viable for stable tasks with 10K+ calls/month
Implementation: Only invest in fine-tuning for tasks where: (1) instructions are stable, (2) volume is high, (3) few-shot examples are large and repetitive. Avoid for evolving tasks or low-volume use cases.
40–75% long-term inference reduction

03B — The 2026 Cost Story

Agentic Token Bloat: When One Request Becomes 50

In the chatbot era, one user message = one API call. In the agentic era, one user message can fan out into 5–50 LLM + MCP tool calls — and a Reflexion loop running 10 cycles consumes 50× the tokens of a linear pass. This is the dominant tokenomics story of 2026, and it's why 73% of enterprises blew past their AI budget.

5–30× cost multiplier vs chatbot baseline

Anyone who modelled costs on chatbot benchmarks is now 5–30× over budget. Microsoft Research: an unconstrained coding agent costs $5–$8 to resolve a single SWE-bench issue.

Reflexion loops compound exponentially

A self-critique loop running 10 cycles consumes 50× the tokens of a single linear pass. Without circuit breakers, a stuck ReAct loop can burn $50/min on frontier models.

Memory writes are silent token costs

Episodic memory writes (MemOS, Mem0, Zep) and skill-doc generation (Hermes Agent pattern) consume output tokens. Budget for them in OTEL gen_ai.tokens.write spans.

Cost-per-Task replaces cost-per-token

The 2026 SLO unit: cost-per-resolved-task, not cost-per-token. September's proof points: GPT-6 Astra costs 2.5× GPT-5.6 Sol per token but finishes OSWorld tasks in ~47% less time with fewer tokens (vendor); GPT-6.1 Sol costs $5.47 per Terminal-Bench Science task vs Astra's $23.80; and Grok 4.7 doubled cost per task vs Grok 4.6 at the identical $2/$6 price. 04 — Advanced Techniques

Infrastructure-Level Optimisation

Beyond prompt-level changes, these infrastructure techniques address token costs at the compute layer — particularly relevant for self-hosted deployments and high-scale agentic systems.

A
Self-Hosted

KV Cache Compression

For self-hosted deployments, the KV (key-value) cache is the dominant memory bottleneck. Recent research shows 70–90% memory reduction is achievable with minimal accuracy loss — enabling longer contexts on the same hardware.

2026 state-of-the-art (ICLR 2026)
  • Google TurboQuant: 6× memory reduction, zero accuracy loss, no calibration
  • NVIDIA KVTC: Up to 20× compression via PCA + entropy coding
  • FastKV: 1.82× faster prefill + 2.87× faster decoding vs baseline
  • FP8/INT4 quantisation: 2–4× memory reduction, supported in vLLM natively
Implementation: Use vLLM with PagedAttention for 14–24× higher throughput vs naive implementations. Apply FP8 KV quantisation on NVIDIA Hopper/Blackwell GPUs. For cutting-edge: TurboQuant/KVTC were presented at ICLR (April 2026).
6–20× memory reduction → lower hardware cost
B
Self-Hosted

Speculative Decoding

Pair the target model with a lightweight draft model that proposes multiple tokens simultaneously. The target model verifies the batch in a single forward pass — achieving 2–5× faster generation with identical output quality.

2026 benchmarks
  • Standard speculative decoding: 2–4× faster inference
  • Speculative Speculative Decoding (Saguaro): 5× vs autoregressive
  • 14–17% throughput gain on Oracle OCI with A100 GPUs
  • Zero accuracy degradation — output is mathematically equivalent
Implementation: Supported natively in vLLM, SGLang, and TRT-LLM. DeepSeek uses Multi-Token Prediction (MTP) heads as a draft mechanism. EAGLE/EAGLE-2 are the most widely deployed speculative decoding variants as of 2026.
2–5× throughput increase → lower GPU hours per token
C
Agentic Systems

Agentic Workflow Optimisation

Multi-agent systems can consume 4–15× more tokens than single-agent calls if not carefully orchestrated. Parallel execution, tool fusion, and model tiering within agent graphs dramatically reduce token overhead.

Key agentic cost patterns
  • DAG-based topologies: Parallel instead of sequential tool calls
  • Tool fusion: Combine related tool calls → 12–40% token reduction
  • Model tiering: Haiku for sub-tasks, Sonnet for orchestration, Opus for core reasoning
  • Agent cost pre-estimation: Use LLM to evaluate plan cost before execution
  • Token quotas: Hard-cap tokens per agent per session to prevent runaway costs
Implementation: Set monthly quota limits ($) in agent platforms. Set execution limits per minute to prevent runaway loops. Set time limits per conversation. Track cost per agent per task. Source: Tonic3 Agentic Budget Framework 2025.
12–40% token reduction in multi-agent systems
D
Infrastructure

Model Quantisation (Self-hosted)

Quantisation reduces model weight precision from FP16 to INT8 or INT4, cutting memory requirements by 2–4× with minimal quality loss. Enables running larger models on cheaper hardware.

Quantisation options
  • FP8 (8-bit): 2× memory savings, near-zero quality loss
  • INT4 (4-bit): 4× memory savings, <5% accuracy delta on most tasks
  • Llama 70B at INT4: runs on 2× A100 80GB vs 4× in FP16
  • Libraries: bitsandbytes, AutoGPTQ, GGUF (llama.cpp)
  • H100 GPUs: 80% more cost-efficient per token vs older hardware
Implementation: Use INT8 for production serving as the conservative default. Use INT4 for less critical inference workloads where you've tested quality. Always benchmark quality on your specific task before deploying quantised models.
2–4× memory reduction → lower infrastructure cost

07 — The Playbook

How to Do Tokenomics: Do's & Don'ts

Everything above, distilled into an operating doctrine — October 2026 edition. The through-line: architecture beats prompt tweaks, measurement beats intuition, and cost-per-completed-task beats every per-token metric. A cheaper path that silently drops quality is the most expensive mistake in this entire guide.

✅

Do

Proven in production
  • ✓ Instrument before you optimise. OTEL gen_ai spans; tag every call with model, team & use-case. You cannot cut what you cannot see
  • ✓ Benchmark cost-per-completed-task, not $/MTok — tokenisers diverge ~30%, token appetite roughly doubles between model versions (Grok 4.7 vs 4.6) and runs ~13× between effort levels (Sonnet 5.5 max vs medium)
  • ✓ Build an eval harness first. A 200-pair golden set is the licence to downshift models — without evals you can't tell whether the cheaper path held quality
  • ✓ Cache what repeats. Prompt caching first (90–97.5% off input at the big labs; ~98% on DeepSeek), semantic caching second. Stable prefix first, dynamic content last
  • ✓ Route by task difficulty — 70/25/5 cascade with a confidence threshold, and re-tier monthly while the price war lasts
  • ✓ Engineer context just-in-time. Retrieve the snippet, not the repo: 2–3 tight chunks beat 8 long documents at over half the input cost
  • ✓ Batch what can wait — 50% off at OpenAI, Anthropic and Google, and schedule non-urgent jobs outside DeepSeek's 2× peak window (Mon–Fri Beijing business hours)
  • ✓ Set budget caps & circuit breakers before launch — $ per agent per session, loop detection, kill switches. Day one, not after the first bill
  • ✓ Model both rates of intro pricing — Gemini 3.8 Flash doubles to $1.50/$7.50 on Jan 1, 2027, Gemini 4 Argon goes from $2/$10 to $4/$20 and GPT-5.6 Sol's $4/$20 promo is only guaranteed to Nov 21
  • ✓ Set effort explicitly on every call — Opus 5.5 defaults to medium, Sonnet 5.5 to high; max effort can cost 10×+ medium per task
  • ✓ Keep an exit path. An OpenAI-compatible gateway (LiteLLM, Portkey, Bifrost) makes a lab's repricing a config change, not a rewrite
🚫

Don't

The 2026 failure modes
  • ✗ Don't compare $/MTok across tokenisers. The same text costs ~30% more tokens on Claude Opus 4.7+/Opus 5.5/Fable 5.1/Sonnet 5.5 than on earlier Claude models
  • ✗ Don't project agentic costs from chatbot benchmarks — the 5–30× fan-out multiplier is why 73% of enterprises blew their AI budget
  • ✗ Don't assume more context = better answers. Context bloat dilutes quality and costs more — it's the single biggest source of token waste
  • ✗ Don't run reasoning models on simple tasks — classification, FAQ and summarisation on extended thinking pays 5–20× for invisible chain-of-thought
  • ✗ Don't let an uncapped budget meet a stuck loop. A runaway ReAct loop on a frontier model burns $50/min
  • ✗ Don't chase the cheapest sticker price without a verification budget — if outputs need a human or a checker model to trust, that cost belongs in the comparison (Grok 4.5's elevated hallucination rate taught that lesson back in July)
  • ✗ Don't lock into one lab's tier structure. Five major launches in four weeks (Sep 1–29) means last month's tier math is already stale
  • ✗ Don't assume open-weight = free or price-stable. GLM-5.3 needs ~750GB of FP8 weights to self-host, and DeepSeek now bills 2× at peak hours
  • ✗ Don't ignore long-context cliffs — GPT-6 reprices the WHOLE request past 272K input tokens, Grok past 200K, Gemini 3.1 Pro past 200K
  • ✗ Don't treat intro pricing as permanent in any projection a CFO will see
  • ✗ Don't hand-polish prompts before fixing architecture. System prompts, history, tool schemas and retrieval dominate spend — not user phrasing
🗓️

Your First 30 Days

Sequenced runbook
  • Week 1 — Baseline. Wire OTEL gen_ai spans, tag by model/team/use-case, stand up a cost-per-task dashboard. No optimisation yet — you need a before picture
  • Week 2 — Free wins. Turn on prompt caching, set effort explicitly and shift non-real-time work to batch endpoints. Zero quality risk, typically 50–70% off eligible spend
  • Week 3 — Route. Build the 200-pair golden set, then pilot cascade routing on your single highest-volume intent. Measure quality deltas, not vibes
  • Week 4 — Govern. Budget hard caps per agent, circuit breakers, loop detection, and a monthly re-tier review. The price war makes the review cadence load-bearing
  • Ongoing. Alarm on cost.per_task p95 > 2× baseline; re-shop the pricing table monthly; re-run the golden set on every model or prompt change
Typical outcome: 70–85% spend reduction at held quality
